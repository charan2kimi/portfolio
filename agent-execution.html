Architecture

Five planes. The agent plane does the work; the policy plane decides what each step may touch and re-decides on every call; the model plane decides what it runs on and what it costs; the observability plane proves what happened. Every enforcement point is marked.

One invocation under policy

  1. Request arrives. Tenant and identity bind at the door; the policy decision point resolves tool entitlements, data boundaries, and model class before any agent work starts.
  2. The harness plans. ReAct reasons over which governed tools to call; CodeAct composes tool use as code that will only ever run inside the sandbox.
  3. Every tool call hits an enforcement point. Discovery was already filtered to the identity's entitlements; scope is re-evaluated at call time; the AST gate checks imports, secrets, and runtime limits on every execution step.
  4. Retrieval runs as a tool. Hybrid BM25 plus kNN retrieval with reciprocal rank fusion and query decomposition pulls evidence from the in-tenant corpus.
  5. The per-run judge corrects. A per-run judge checks the draft against retrieved evidence, catching hallucinations and false gaps before synthesis completes.
  6. The gateway routes the model call. The platform policy layer computes the attribute-based decision; LiteLLM enforces it via virtual keys, model allowlists, and budgets; cost is emitted per call.
  7. Rails on the way in and out. PII detection and redaction plus content moderation run on inputs and outputs; in HIPAA deployments this path is not optional.
  8. Results stream. SSE for interactive sessions; background workers for long jobs.
  9. The trace lands. Spans, logs, and telemetry make the invocation replayable; the online production eval scores the live traffic; the audit trail records which policies decided what.

Key decisions

Authorization decided inside the agent loop, not at the session door

Decision: the platform policy layer is the decision point; enforcement points sit at the tool-call boundary inside the agent loop, so the attribute-based decision is recomputed on every invocation rather than minted once at login.

Alternative considered: a session-scoped grant issued at entry and trusted for the rest of the run.

Consequence: a prompt-injected or misplanned step hits a deny-by-default wall the moment it reaches for a tool outside its entitlements, and delegation across tool chains cannot silently widen scope. This is the runtime enforcement pattern Cedar-style agentic authorization now formalizes.

An AST-gated interpreter for semi-trusted code

Decision: user-authored agent code runs in a per-tenant sandbox whose interpreter enforces import allowlists, secrets scanning, and runtime limits at parse time and on every execution step.

Alternative considered: a platform engineer reviews every analyst code change before it can run.

Consequence: semi-trusted analyst code reaches a live multi-tenant runtime without per-change review; the isolation boundary, not a process document, is what makes that safe. And only artifacts DevX has tested and published can execute at all, so the sandbox is the second gate, not the only one.

Three eval loops, kept distinct

Decision: keep three things separate. The golden-dataset gate scores models, agents, and RAG agents against versioned datasets in CI and blocks regressions before release. The per-run judge is a runtime component inside live RAG agents, correcting each run. Online production eval is a third loop scoring live traffic after release.

Alternative considered: collapse them: gate on the runtime judge's scores, or test only before release with nothing watching production.

Consequence: the release gate is reproducible and cheap to rerun; the runtime judge does the per-run correction only it can do; drift that never appeared in the golden set still gets caught in production. Quality has a gate, a corrector, and a heartbeat, and none of them is mistaken for another.

The three layers

Data layer

Hybrid OpenSearch retrieval indexes (BM25 lexical plus kNN vector) and versioned golden datasets over the regulated corpus, fed by DevX's ingestion pipelines (Airflow plus Spark). Self-hosted embeddings keep the corpus in-tenant end to end, with zero per-token cost at 50,000+ documents monthly.

Product layer

The DSPy harness, agentic RAG, and the policy plane are the product: agents that analyst teams trust with regulated work because every capability is entitlement-scoped, sandboxed, and traced. Cost is a product surface: budgets, model allowlists, and per-call cost emission are visible to the teams that own the spend.

Deployment layer

Per-client multi-tenant deployments in regulated environments, HIPAA included; tenants pin to private models for data residency. Compliance review gets what it asks for: a SOC-aligned audit trail built on the trace, log, and telemetry evidence, with a replayable trace behind every answer.
