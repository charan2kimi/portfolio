One transaction

  1. Ingress, streamed not buffered. The transaction enters over any mediated protocol and is normalized into the 4-stage pipeline without buffering the payload; memory reservation admits it or sheds it with an explicit error.
  2. Screening runs cheapest first. Network rules, then application filters, then firewall signatures; intrusion sensors can block, throttle, alert, or quarantine on the spot.
  3. Identity resolves once. One of the 11 authentication methods authenticates the caller; the credential cache answers most lookups without a roundtrip; throttling and replay caches guard the door.
  4. Federation happens at the edge. A SAML assertion is issued or consumed, or an OAuth token is minted or validated against the per-policy token caches; backends never do their own identity plumbing.
  5. Message security is enforced. Signatures are verified or applied, certificate chains are path-validated with cached revocation checks, and payloads are decrypted or encrypted per policy.
  6. The policy pipeline executes. Composed processors run in stages, with sandboxed inline JavaScript covering the last mile; every stage is bounded by a timing checkpoint.
  7. Cache, then balance. The cache answers hits immediately and coalesces concurrent misses into one backend call; on a true miss, a balancing strategy places it, with health checks and failover behind it.
  8. Egress with attribution and evidence. The response streams back through response processing and delivery; the checkpoints attribute the latency, signed logs flow to the SIEM, and alerting fires if a threshold tripped.

Key decisions

Stream, never buffer

Decision: a zero-copy, 4-stage bidirectional streaming pipeline with per-transaction memory reservation and backpressure that answers overload with an explicit error.

Alternative considered: buffer-and-forward proxying: read the whole message, then operate on it. Simpler to write and debug.

Consequence: at 10B+ transactions a day in aggregate the arithmetic closes only one way. Zero-copy keeps per-transaction memory near constant, large objects move through the same machinery as small calls, and overload degrades by deliberate load shedding instead of collapse.

Cache and coalesce, not bigger backends

Decision: a multi-tier response cache, in-memory, disk, and Redis, with request coalescing so concurrent misses for one key become one backend call, all configured through no-code cache policies.

Alternative considered: scale the backends behind the gateway and let every miss through.

Consequence: backend load fell 40-70%, cache stampedes stopped being an outage class, and the caching behavior became something an operator configures per API instead of something a developer codes per integration.

Configuration as the product, code as the escape hatch

Decision: a no-code builder of dozens of processors, sitting on the product's versioned configuration framework, with sandboxed inline JavaScript reserved for the last mile.

Alternative considered: a scripting-first gateway where every policy is code. Maximum flexibility, minimum governance.

Consequence: policies became reviewable, versionable, promotable artifacts instead of scripts, onboarding a new API fell from weeks to hours, and years later the same shape returned as the governance layer on agent tools.

Active-passive with a virtualized network identity, not active-active

Decision: one active appliance and one passive, with the survivor assuming the pair's network identity so neighbors keep forwarding without relearning, split-brain prevention so only one node ever owns it, and sub-minute recovery.

Alternative considered: active-active clustering: better utilization, but state synchronization and split-brain hazards multiply on a stateful security workload.

Consequence: failover is deterministic with sub-minute recovery, and 99.99% uptime held on workloads where a split brain would mean two gateways making conflicting security decisions.

What the AI stack inherited

Policy pipeline → tool governance

A policy pipeline composed without code, versioned and audited, is the direct ancestor of the governance layer on agent tools in the document AI and agent platform and in DevX: scoped authorization and audit attached to the artifact instead of hand-written per integration.

Identity brokering → tenant identity

An authentication subsystem with 11 methods behind one interface, plus caching and connection pooling that eliminated 90%+ of directory roundtrips, taught the pattern the AI stack uses for Okta, GitHub, and local identity: resolve identity once at the edge, scope everything behind it.

Stage checkpoints → agent tracing

The timing checkpoints that attribute gateway latency stage by stage became span-level trace attribution in the agent harness: same discipline, new substrate. When an agent run is slow, the trace names the hop that spent the time, exactly as the pipeline did for a transaction.
