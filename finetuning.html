Architecture

Five planes in time order. Data is versioned before anything trains; training is engineered for spot economics; the checkpoint lifecycle turns every run into a steerable artifact; the gate approves; deployment serves and observes. The dataset versioning here is the same system that feeds evals and agent use cases in DevX and the Agent Execution Platform, so training, evaluation, and runtime agree on the data.

Dataset to production model

  1. A corpus lands. Upload, API stream, or queue consumer; Airflow DAGs run Spark preprocessing into clean records.
  2. A dataset version is cut. Reproducible train / validation / test splits under a numbered version that training, evals, and agent use cases all reference.
  3. Training launches. One workflow onboards the Hugging Face base model and starts SFT as PEFT / LoRA jobs: base weights frozen, low-rank adapters training. SkyPilot places the job on the cheapest spot GPU capacity across AWS and GCP from the compute registry; Ray Train replicates the training loop across provisioned workers.
  4. Memory is engineered, not hoped for. Gradient checkpointing keeps only each block's inputs during the forward pass and recomputes intermediate activations during backward, buying the activation memory that fits larger models and batches on the same GPUs.
  5. The run reports while it trains. Loss and eval metrics stream live into MLflow; checkpoints capture adapter weights, optimizer state, learning-rate schedule, and random state to durable storage at intervals.
  6. Pause. An operator halts the run at its latest checkpoint. Nothing is lost; the run becomes an inspectable artifact instead of a moving target.
  7. Inspect and evaluate the checkpoint. The paused checkpoint is scored against a pinned versioned eval dataset, the same versions the release gate will use, before more GPU hours are committed.
  8. Resume, branch, or stop. Continue from the latest checkpoint, replay from any earlier one to branch a new run, or kill the run on the evidence. Spot preemption triggers the same machinery: SkyPilot provisions replacement capacity and the job reloads its latest checkpoint.
  9. The CI gate decides. MLflow compares surviving candidates across runs; LLM-as-judge scoring plus human review approve or reject every model. Nothing deploys on metrics alone.
  10. Registry, serving, agent platform. Approved versions register with full lineage, dataset version to run to model version to deployment, then serve on GPU-backed vLLM and register into the Agent Execution Platform's LiteLLM gateway as tenant-pinnable private models, monitored in OpenSearch beside their training history.

Key decisions

Spot capacity with checkpoint recovery, not on-demand fleets

Decision: orchestrate training onto spot GPU capacity across AWS and GCP with SkyPilot; every job writes checkpoints to durable cloud storage, and on preemption the orchestrator provisions replacement capacity, in another region or cloud when needed, and the job resumes from its latest checkpoint.

Alternative considered: reserved or on-demand GPU fleets, paying a premium for capacity that cannot be reclaimed.

Consequence: training cost dropped enough to make 20+ per-client production models economically routine. The price was disciplined checkpointing, and that discipline became a product feature: the same checkpoints that survive preemption power pause, resume, and replay.

Adapters, not full-parameter fine-tunes

Decision: run SFT through PEFT with LoRA adapters: base weights stay frozen while small low-rank matrices train and ship as the per-client artifact.

Alternative considered: full-parameter fine-tuning per client.

Consequence: per-client models became tractable in GPU memory and storage: one base plus small adapters, trained on smaller capacity, iterated faster. Paired with gradient checkpointing, the same spot hardware stretched to larger models and batches.

Checkpoints as a control surface, not crash insurance

Decision: expose pause, inspection, mid-training evals against versioned datasets, and resume or replay from any checkpoint as first-class operations on every run.

Alternative considered: checkpoints as an internal fault-tolerance detail, written on schedule and touched only by automated recovery.

Consequence: bad runs die at the first failing checkpoint eval instead of burning GPU hours to completion; promising runs branch from a known-good checkpoint; and because steering and recovery share one mechanism, spot preemption became a non-event.

Judge plus human as the CI gate

Decision: run LLM-as-judge scoring plus human review as the CI gate on every model; nothing deploys on metrics alone.

Alternative considered: automated metric thresholds alone.

Consequence: regulated clients get a defensible release trail, scores plus a named human approval, and judge blind spots do not ship silently. The gate scores against the same versioned eval datasets used mid-training, so a model is approved on the evidence that steered it.

The three layers

Data layer

Versioned datasets are the spine. Airflow DAGs with Spark processing turn file uploads, API streams, and queue-fed Excel and JSON corpora into numbered dataset versions with reproducible train / validation / test splits. The same versions serve fine-tuning, mid-training checkpoint evals, release evals, and agent use cases, so every consumer scores against identical data by version ID.

Product layer

One workflow from Hugging Face base model onboarding through SFT launch, live metrics, checkpoint steering, comparison in MLflow, and the judged release gate. A domain team produces a governed model without owning GPUs or orchestration; pausing a run, scoring a checkpoint, and branching from it are product operations, not infrastructure surgery.

Deployment layer

Registered hardware and cloud compute targets define placement for training and serving. vLLM serves approved models on GPU; each registers into the Agent Execution Platform's LiteLLM gateway as a tenant-pinnable private model. Audit rides MLflow tracking plus OpenSearch logging, with OpenTelemetry instrumentation platform-wide: full lineage from dataset version to run to model version to deployment.
