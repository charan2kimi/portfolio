Architecture

Five planes in time order. Data is versioned before anything trains; training is engineered for spot economics; checkpoints turn every run into something an operator can pause, inspect, and resume; the gate approves; deployment serves behind the same gateway every other model uses.

Dataset to production model

  1. A corpus lands. Upload, API stream, or queue consumer; scheduled pipelines run the preprocessing into clean records.
  2. A dataset version is cut. Reproducible train / validation / test splits under a numbered version that training, evals, and agent use cases all reference.
  3. Training launches. One workflow onboards the Hugging Face base model and starts PEFT / LoRA training: base weights frozen, low-rank adapters training. SkyPilot places the job on the cheapest spot GPU capacity across AWS and GCP; Ray Train replicates the loop across the provisioned workers.
  4. Memory is traded for compute. Gradient checkpointing keeps only each block's inputs during the forward pass and recomputes activations during backward, buying the memory that fits larger models and batches on the same GPUs.
  5. The run reports while it trains. Loss and eval metrics stream into MLflow; checkpoints capture adapter weights, optimizer state, learning-rate schedule, and random state at intervals.
  6. Pause. An operator halts the run at its latest checkpoint. Nothing is lost; the run becomes an inspectable artifact instead of a moving target.
  7. Resume or stop. Continue from the latest checkpoint or kill the run on the evidence. Spot preemption triggers the same machinery: SkyPilot provisions replacement capacity and the job reloads its latest checkpoint.
  8. The gate decides. MLflow compares surviving candidates across runs; the model is tested against the held-out split and approved by name. Nothing deploys on metrics alone.
  9. Registry, serving, gateway. Approved versions register with their lineage, then serve on vLLM and register into the platform's gateway as private models.

Key decisions

Spot capacity with checkpoint recovery, not on-demand fleets

Decision: provision training onto spot GPU capacity across AWS and GCP with SkyPilot; every job writes checkpoints to durable storage, and on preemption the orchestrator provisions replacement capacity and the job resumes from its latest checkpoint.

Alternative considered: reserved or on-demand GPU fleets, paying a premium for capacity that cannot be reclaimed.

Consequence: training cost dropped enough to make 20+ production models at enterprise firms economically routine. The price was disciplined checkpointing, and that discipline became a product feature: the same checkpoints that survive preemption power pause and resume.

Adapters, not full-parameter fine-tunes

Decision: train through PEFT with LoRA adapters: base weights stay frozen while small low-rank matrices train and ship as the per-firm artifact.

Alternative considered: full-parameter fine-tuning per firm.

Consequence: per-firm models became tractable in GPU memory and storage: one base plus small adapters, trained on smaller capacity, iterated faster. Paired with gradient checkpointing, the same spot hardware stretched to larger models and batches.

Checkpoints as a control surface, not crash insurance

Decision: expose pause, inspection, and resume from any checkpoint as first-class operations on every run, with the MLflow run wrapped around the job for observation.

Alternative considered: checkpoints as an internal fault-tolerance detail, written on schedule and touched only by automated recovery.

Consequence: bad runs stop at the first bad checkpoint instead of burning GPU hours to completion, and because steering and recovery share one mechanism, spot preemption became a non-event.

Testing and approval as the release gate

Decision: a model ships only after tests against the versioned eval sets and a named approval; nothing deploys on metrics alone.

Alternative considered: automated metric thresholds alone.

Consequence: regulated firms get a defensible release trail, test results plus a named approval, and the gate scores against a held-out split of the same dataset version, so the number a model ships on is one it never trained on.

The three layers

Data layer

Versioned datasets are the spine. Scheduled pipelines turn uploads, API streams, and queue-fed corpora into numbered dataset versions with reproducible train / validation / test splits. The same versions serve training, release tests, and agent use cases, so every consumer scores against identical data by version ID.

Product layer

One workflow from Hugging Face base model onboarding through training launch, live metrics, pause and resume, comparison in MLflow, and the release gate. A domain team produces a governed model without owning GPUs or orchestration; pausing a run and resuming it are product operations, not infrastructure surgery.

Deployment layer

Approved models serve on vLLM, with serving parameters tuned per deployment, and register into the platform's gateway as private models under the same access policies as every other model.
